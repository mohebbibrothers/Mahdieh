# درخواست کد الگوی پیامک از پنل ایران‌پیامک

این برگ، متن آمادهٔ ارسال به پشتیبانی پنل است. هر الگو که کدش برسد، **بدون تغییر
کد برنامه** فعال می‌شود: کد را در متغیر محیطی `SMS_PATTERN_CODES` (JSON) بگذارید و
سرویس را ری‌استارت کنید — نمونه:

```bash
SMS_PATTERN_CODES='{"offer_created": "کددریافتی", "booking_reminder": "کددریافتی"}'
```

بازتولید همین برگ (خروجی فرمان تمیز و پیپ‌پذیر است):

```bash
make sms-patterns ARGS="--request" > docs/sms/pattern-request.md
```

وضعیت را هر وقت خواستید ببینید (بدون تماس با شبکه):

```bash
make sms-patterns                   # جدول وضعیت
make sms-patterns ARGS="--json"     # خروجی ماشین‌خوان برای پایش
make sms-patterns ARGS="--check"    # کد خروج ۱ اگر قالب حیاتی بدون الگو باشد
```

## چرا این هفت الگو مهم‌اند؟

| اولویت | قالب مهدیه | اگر نباشد چه می‌شود؟ |
| --- | --- | --- |
| **حیاتی** | `offer_created` | قلب صف انتظار: سانس آزاد می‌شود و زائر باخبر نمی‌شود |
| بالا | `booking_reminder` | عدم‌حضور بیشتر؛ سانسِ رایگان هدر می‌رود |
| بالا | `booking_cancelled` | زائر مطمئن نیست سانسش آزاد شده؛ تلفن پذیرش پر می‌شود |
| متوسط | `waitlist_joined` / `waitlist_requeued` / `offer_accepted` | زائر نوبتش را نمی‌داند و چند بار ثبت می‌کند |
| متوسط | `feedback_request` | نظرسنجی پس از اقامت دیده نمی‌شود |
| — | `booking_moved` | فعلاً به «تأیید رزرو» افت می‌کند (متن درست، ولی اختصاصی نیست) |
| اختیاری | `staff_alert` / `dry_run` | هشدار عملیاتی کارکنان و آزمون سالم‌بودن پنل |

## متن درخواست (همان که برای پشتیبانی پنل می‌فرستیم)

```text
سلام، برای سامانهٔ زائرسرای مهدیه به چند الگوی پیامک نیاز داریم.
لطفاً برای هر مورد، یک الگو بسازید و «کد الگو» را برای ما بفرستید.
پیش‌شمارهٔ همهٔ متن‌ها: «تموم زندگیم مال حسینه...»

۱. «لغو رزرو» — کد قالب مهدیه: booking_cancelled
   متن پیشنهادی: {name} عزیز، رزرو {code} لغو شد و سانس آزاد گردید.
   متغیرها: {name}، {code}

۲. «یادآور پیش از پذیرش» — کد قالب مهدیه: booking_reminder
   متن پیشنهادی: {name} عزیز، یادآوری پذیرش {unit} در {date} — زائرسرای امام زمان (عج).
   متغیرها: {name}، {unit}، {date}

۳. «پیشنهاد سانس آزادشده (نوبت انتظار)» — کد قالب مهدیه: offer_created
   متن پیشنهادی: {name} عزیز، سانس مورد نظر شما آزاد شد: {unit}، {window}. پذیرش با یک ضربه: {link}
   متغیرها: {name}، {unit}، {window}، {link}

۴. «پایان فرصت پیشنهادها» — کد قالب مهدیه: waitlist_requeued
   متن پیشنهادی: {name} عزیز، در بازهٔ {window} سانس مناسبی آزاد نشد؛ درخواست شما بسته شد.
   متغیرها: {name}، {window}

۵. «تأیید پذیرش پیشنهاد» — کد قالب مهدیه: offer_accepted
   متن پیشنهادی: {name} عزیز، پیشنهاد را پذیرفتید و {unit} به نام شما ثبت شد.
   متغیرها: {name}، {unit}

۶. «ثبت درخواست انتظار» — کد قالب مهدیه: waitlist_joined
   متن پیشنهادی: {name} عزیز، درخواست انتظار شما برای {unit} در {window} ثبت شد.
   متغیرها: {name}، {unit}، {window}

۷. «نظرسنجی پس از اقامت» — کد قالب مهدیه: feedback_request
   متن پیشنهادی: {name} عزیز، اقامت شما در {unit} چطور بود؟ پاسخ چند ثانیه‌ای: {link}
   متغیرها: {name}، {unit}، {link}

همچنین کد الگویی که ساخته‌اید ولی کدش را نگرفته‌ایم:
  • لغو رزرو — قالب مهدیه: booking_cancelled
  • یادآور پیش از پذیرش — قالب مهدیه: booking_reminder
  • پیشنهاد سانس آزادشده (نوبت انتظار) — قالب مهدیه: offer_created
  • پایان فرصت پیشنهادها — قالب مهدیه: waitlist_requeued
  • تأیید پذیرش پیشنهاد — قالب مهدیه: offer_accepted
  • ثبت درخواست انتظار — قالب مهدیه: waitlist_joined
  • نظرسنجی پس از اقامت — قالب مهدیه: feedback_request
  • هشدار عملیاتی کارکنان — قالب مهدیه: staff_alert
  • پیام آزمایشی — قالب مهدیه: dry_run
```

## قاعده‌ای که هرگز نباید بشکند

پیام **ناقص** هرگز برای زائر نمی‌رود. اگر متغیر الزامی یک الگو پیدا نشود، ارسال
«مسدود» ثبت می‌شود (نه ارسال با جای‌خالی پرنشده) و در گزارش‌ها با دلیل روشن دیده
می‌شود. همین قاعده آزمون دارد: `src/tests/test_sms_pattern_readiness.py`.
