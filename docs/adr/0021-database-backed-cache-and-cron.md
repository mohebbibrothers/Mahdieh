# ADR-0021 — کش، نشست و کارهای پس‌زمینه روی پایگاه‌داده و cron

- **وضعیت:** پذیرفته‌شده
- **تاریخ:** ۱۴۰۵/۰۷/۲۷
- **تکمیل‌کنندهٔ:** ADR-0011 (تعویق زیرساخت سنگین)، ADR-0007 (صندوق خروجی و ابطال Epoch)
- **وابسته به:** ADR-0020

## زمینه

میزبان cPanel نه Redis/Valkey دارد، نه اجازهٔ فرآیند دائمی (سقف ۵۰ فرآیند و ۲۰ ورودی
هم‌زمان LVE)، نه systemd. پیش‌تر کش، نشست، سقف نرخ و قفل‌ها روی Valkey بودند و رلهٔ
صندوق خروجی یک سرویس دائمی بود.

## تصمیم

1. **کش جنگو روی جدول** (`django_cache`) با پشتانهٔ `AtomicDatabaseCache`
   (`apps/core/db/cache.py`): `incr`/`decr` با یک دستور SQL اتمیک (`UPDATE … SET value =
   value + n`)، نه خواندن-نوشتن. آزمون رشته‌ای نشان داد `DatabaseCache` استاندارد از ۲۰۰
   افزایش هم‌زمان فقط ۳۹ را ثبت می‌کند و نسخهٔ اتمیک هر ۲۰۰ را.
   - روی نام مستعار جداگانهٔ `cache` (آینهٔ `default`) تا نوشتهٔ کش با برگشت تراکنش
     درخواست پاک نشود — همان معنای Redis.
   - استقرار باید `createcachetable` را اجرا کند (در `deploy.sh` و `entrypoint.sh` هست).
   - در آزمون‌ها LocMem می‌ماند (DDL در MySQL تراکنش را ضمنی commit می‌کند).
2. **نشست‌ها** روی پایگاه‌داده (`sessions.backends.db`) با جاروب روزانهٔ `clearsessions`.
3. **کارهای پس‌زمینه** بدون فرآیند دائمی: `crontab` + `deploy/cpanel/cron_run.sh`
   (تک‌نمونگی با `flock`، سقف زمان با `timeout`، لاگ چرخشی ۵ مگابایتی).
   - رلهٔ صندوق خروجی هر دقیقه با `--loop --interval 5 --max-seconds 55` اجرا می‌شود ⇒
     تأخیر پیامک ≤ ۵ ثانیه، بدون فرآیند همیشه‌روشن.
   - کد ورود (OTP) **هم‌زمان** فرستاده می‌شود، نه از صف؛ کاربر منتظر پیامک نمی‌ماند.
   - همان کارها برای سرور اختصاصی در `deploy/systemd` هم نگه داشته شده‌اند.

## پیامدها

- **مثبت:** یک وابستگی زیرساختی کمتر؛ پشتیبان پایگاه‌داده کش و نشست را هم دارد؛ رفتار
  تولید در CI عیناً آزموده می‌شود.
- **منفی:** هر درخواست کش یک پرس‌وجوی SQL است (برای ۵ واحد و ترافیک زائر ناچیز است).
  اگر روزی بار بالا رفت، تعویض پشتانهٔ کش یک خط تنظیمات است.
- **شرط بازنگری:** اگر میانهٔ زمان پاسخ زیر بار واقعی از ۳۰۰ میلی‌ثانیه گذشت یا میزبان
  Redis فراهم کرد.

## گزینه‌های ردشده

- **Redis بیرونی (ابری):** تأخیر شبکه از ایران و نقطهٔ شکست بیرونی.
- **کش حافظه‌ای (LocMem) در تولید:** بین فرآیندهای Passenger مشترک نیست ⇒ سقف نرخ و
  ابطال Epoch بی‌معنا می‌شوند.
- **Celery با پایگاه‌داده به‌عنوان بروکر:** فرآیند دائمی می‌خواهد و برای این بار سنگین است.
