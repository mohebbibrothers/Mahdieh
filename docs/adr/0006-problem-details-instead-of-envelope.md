# ADR-0006: RFC 9457 (Problem Details) به‌جای پوشش پاسخ سفارشی

**وضعیت:** پذیرفته (شکستن آگاهانهٔ الگوی پروژهٔ پیشین) · **تاریخ:** ۲۰۲۶-۱۰-۱۵

## زمینه
الگوی رایج در پروژهٔ پیشین، پوشش `{success, status_code, message, data}` بود. کارفرما خواسته «از همه‌جهت قله باشد»؛ یعنی استاندارد جهانی بر سلیقهٔ داخلی مقدم است.

## تصمیم
- **خطا:** بدنهٔ استاندارد **RFC 9457** با `type`, `title`, `status`, `detail`, `instance` + افزونه‌های دامنه‌ای (`code`, `errors`, `trace_id`, `alternatives`).
- **موفقیت:** بدنهٔ خالصِ منبع + هدرهای معنادار (`ETag`, `Location`, `RateLimit-*`, `Deprecation`).
- `Content-Type: application/problem+json`.

## چرا
- ابزارهای جهانی (کلاینت‌ها، Gatewayها، SDKها) RFC 9457 را می‌فهمند؛ پوشش سفارشی را نه.
- افزونه‌های دامنه‌ای اجازه می‌دهند در تصادم رزرو، **گزینه‌های جایگزین** را هم بفرستیم.
- پوشش موفقیت، بدنه را متورم و کش HTTP را سخت‌تر می‌کند.

## پیامدها
- ✅ سازگاری با استاندارد و ابزارها؛ کش‌پذیری بهتر
- ✅ خطاهای غنیِ دامنه‌ای (مثل `reservation_conflict` با فهرست جایگزین‌ها)
- ⚠️ تغییر قرارداد نسبت به پروژهٔ قبلی — عمدی و مستند
- ⚠️ مستندسازی افزونه‌ها در OpenAPI الزامی است تا SDK درست تولید شود
