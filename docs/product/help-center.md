# میز راهنما — سند مالکیت محتوا

این سند برای **کسی** نوشته شده که روزی می‌خواهد یک پرسش به راهنما اضافه کند یا
پاسخی را عوض کند؛ نه یک برنامه‌نویس لازم است، نه انتشار نسخهٔ جدید.

## چرا راهنما در کد زندگی می‌کند؟

متن‌های راهنما **قرارداد محصول** هستند: هر جمله یا از قاعدهٔ موتور می‌آید
(کوتاه‌ترین/بلندترین اقامت، افق رزرو، مهلت لغو، سهمیه) یا از پیکربندی استقرار
(تلفن پذیرش). اگر این متن‌ها در پایگاه‌داده و جدا از کد باشند، دیر یا زود با
موتور ناهماهنگ می‌شوند و سامانه به کاربر «دروغ» می‌گوید. پس متن کنار کد است،
ولی **مقدارها** از سیاست زنده پر می‌شوند.

| فایل | نقش |
| --- | --- |
| `src/apps/web/help_content.py` | دسته‌ها، پرسش‌ها، گام‌ها، چک‌لیست پذیرش |
| `src/apps/web/views_help.py` | نماها، جست‌وجو، دادهٔ ساخت‌یافتهٔ `FAQPage` |
| `src/apps/web/templates/web/help.html` | صفحهٔ میز راهنما |
| `src/apps/web/templates/web/help_guide.html` | برگ چاپی (زائر + پذیرش) |
| `src/tests/test_help_center.py` | نگهبان قرارداد و جست‌وجو |

## افزودن یک پرسش (سه گام)

۱. در `help_content.py`، داخل دستهٔ مناسب، یک `HelpItem` بسازید:

```python
HelpItem(
    slug="late-arrival",  # نشانهٔ آدرس؛ ASCII و یکتا
    question="اگر شب دیر برسم چه کنم؟",
    answer="… پذیرش تا ساعت {checkout_hour} …",
    steps=("…",),  # اختیاری
    tags=("دیر رسیدن", "شب"),  # دست‌کم دو برچسب (کیفیت جست‌وجو)
    action=HelpAction(label="…", url_name="web:my_reservations"),
    related=("arrival",),  # نشانه‌های پرسش‌های موجود
)
```

۲. اگر در متن عددی گذاشتید، **آن را سخت‌کد نکنید**: از جای‌نگهدارهای
`policy_values()` استفاده کنید (`{max_stay}`، `{cancel_hours}`، `{quota_cells}`، …).
اگر جای‌نگهدار تازه‌ای لازم است، همان را در `policy_values()` اضافه کنید.

۳. آزمون‌ها را اجرا کنید:

```bash
cd src && uv run pytest -q -p no:randomly tests/test_help_center.py
```

## پنج قاعده‌ای که آزمون‌ها تضمین می‌کنند

1. **هیچ جای‌نگهدار ناپریده**: هر `{…}` در متن، در `policy_values()` مقدار دارد.
2. **هیچ عدد لاتین**: عددها با ارقام فارسی و ممیز «٫» به چشم زائر می‌روند
   (نگهبان `tests/test_guest_digits_contract.py` روی `/help/` و `/help/guide/`).
3. **نشانهٔ یکتا و پیوند سالم**: `slug` تکراری نداریم؛ `related` و `action` به
   پرسش/صفحهٔ موجود می‌رسند.
4. **دنبال‌کردن سیاست زنده**: با عوض‌شدن سیاست، متن راهنما هم عوض می‌شود.
5. **جست‌وجوی بخشنده**: «ي/ك» عربی، نیم‌فاصله، اعراب، نویسهٔ نامرئی و ارقام
   فارسی/لاتین همه یکسان می‌شوند؛ منطق جست‌وجو «و» است (همهٔ واژه‌ها باید پیدا
   شوند) و امتیازدهی: پرسش ۵، برچسب ۳، دسته ۲، پاسخ ۲، گام ۱.

## برگ چاپی و آموزش کارکنان

`/help/guide/` یک برگ آمادهٔ چاپ است: چهار گام رزرو برای زائر، جدول قواعد زندهٔ
اقامت و **چک‌لیست پنج‌گامی میز پذیرش** (`STAFF_CHECKLIST`). پیشنهاد می‌شود یک نسخه
پس از هر تغییر سیاست چاپ و روی میز پذیرش نصب شود — تاریخ چاپ در پایین برگ می‌آید
تا معلوم باشد کهنه است.

## کارهایی که با این بخش تمام نشد

- ترجمهٔ عربی/انگلیسی راهنما (فاز انتشار عمومی).
- تصویر و ویدیوی کوتاه آموزشی برای هر گام (نیازمند ضبط میدانی).
- تلفن و نشانی پذیرش باید در پیکربندی استقرار ثبت شود
  (`MAHDIEH_SUPPORT_PHONE`، `MAHDIEH_SUPPORT_ADDRESS`)؛ تا آن زمان راهنما
  بقیهٔ محتوا را کامل نشان می‌دهد و جملهٔ جانشین می‌آورد.
